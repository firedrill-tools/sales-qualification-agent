# Agent working notes

- Entry: `qualify-lead`, `src/sales_qualification/cli.py`; actual LangChain graph/ChatOpenAI loop in `agent.py`. `evidence.py` observes HTTP before SDK usage defaults and tool dispatch. `connector.py` owns native Composio session lifecycle. Do not replace the real frameworks to simplify tests.
- Model: explicit `OPENAI_API_KEY`, `OPENAI_MODEL` or `--model` (default `gpt-6.1-sol`). Eight calls, 30-second per-request HTTP timeout, 4,096 output tokens, no HTTP retries, `store=false`, foreground only. There is no total workflow deadline or billing cap. Both owned OpenAI clients close on every exit.
- Synthetic state: a validated `synthetic=true`, `schema_version=1` JSON workspace, at most 2 MiB. Operations reload committed data and publish atomically. Serialize writers per path; no concurrent transaction or lock is provided. Denied-company reads/writes/replays fail. There is no outbound email/invite delivery.
- Dataset: `northstar-sales` 1.0.0, eight SHA-bound snapshots/four profiles. The busy case has 15 people, 9 companies, 20 messages and historical work. `--list-cases` and `--init-case CASE --workspace NEW_PATH` require no model/key. Initialization copies exact verified bytes privately and refuses overwrite. Reproduce using `scripts/make_fixtures.py`; qualify a new version when changing inputs. The wheel includes all fixtures. Modified state metadata alone does not prove pristine reset; use the actual hash.
- Synthetic writes need `--allow-write`. `--request-id` is caller-owned (otherwise generated); preserve it for retries. Meeting tools cannot replace it. Exact person/slot retries reuse the original; altered bindings fail. Parallel tool batches fail before dispatch, even if returned despite `parallel_tool_calls=false`.
- Composio requires `--allow-live-actions`, `COMPOSIO_API_KEY`, `COMPOSIO_USER_ID`, and `--composio-accounts PATH` selecting one connected test account for each of attio/gmail/googlecalendar. The callable enforces the same opt-in. No local fallback. Read-only by default; `--allow-write` requests CRM updates/calendar creates, with Gmail read-only. Account management, workbench, proxy execution and automatic local file transfer are disabled. Check the session's scope echo before model/tool access; this is not proof of OAuth grants or test-account status.
- Ownership: delete the newly created Composio session on success/failure, even if parsing/tool loading fails after receiving its ID. Cleanup failure retains the ID and fails the invocation; unknown creation outcome stays unknown. Deletion is not rollback, remote cancellation proof or SaaS reset. Hosted actions do not inherit local idempotency guarantees.
- Completion: completed provider status/item plus nonblank terminal assistant answer with no outstanding/malformed tool call. Nonfinal/refused/error output cannot dispatch writes. An outage or failed assessment is not an overall agent score.
- Evidence: JSON stdout only on success. Exit 1 has JSON stderr retaining available raw response usage/output, normalized messages, tool observations, dependency versions and initial/final state hashes; exit 2 is invalid input/configuration. A failure after a committed operation retains its state; unavailable final state remains null. Missing/partial measurements and cost stay unknown. Do not substitute SDK default zeros or last-step usage for actual aggregate evidence.
- Offline gate: `uv sync --locked --dev`, `uv run --no-sync pytest -q`, model-free listing, `uv build --wheel`, `uv run --no-sync python scripts/check_wheel.py`. The 59 checks use actual SDKs over MockTransport, including a fictional advertised connector schema. They do not prove live OpenAI judgment or real hosted action schemas/permissions/side effects.
- External gates: provider keys/budget, connected test accounts and measured live proof, new released Firedrill interface, public visibility/license. No retired integration, private platform code, fabricated result or automatic paid campaign. Keep credentials, private account mappings, customer data and run journals out of Git.
